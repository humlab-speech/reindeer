# EQL v3 — design

Date: 2026-09-19
Status: approved design, not yet planned or implemented
Package: reindeer

## 1. Summary

EQL v3 extends the EMU Query Language with four abilities, implemented against
the `_emuDBcache.sqlite` cache rather than emuR:

1. **Bundle and session properties.** `bundle@duration > 100s`, `session@Age > 10`.
   Media-probe fields, file stats and user metadata are reachable from the query
   language. Bundles and sessions dominate every annotation they contain.
2. **Track predicates.** `mean(fo,20ms) > 300` returns virtual segments covering
   every region where a sliding-window aggregate of a defined track satisfies a
   numeric comparison. `mean`, `median`, `var`; multi-dimensional tracks indexed
   as `fm[1]`.
3. **Full temporal composition.** Track regions compose with annotation terms
   anywhere in a query. `^` degrades to temporal overlap when either side is
   non-hierarchical; `->` becomes temporal adjacency.
4. **Bare level references.** `Word ^ Sentence == "Some sentence"` returns every
   word in those sentences, with no `=~ ".*"` incantation.

EQL2 remains a strict subset in meaning. Nothing that parses today changes
result.

## 2. Goals and non-goals

**Goals**

- EQL2 result parity, verified by the existing 1074-test parity suite running
  with the legacy fallback disabled.
- Track predicates that are affordable on a whole corpus after the first run.
- Parse errors that point at a character offset instead of failing a regex.
- Lazy pipelines (`lazy_segment_list`) keep working when track terms appear.

**Non-goals**

- A full thirteen-relation Allen interval algebra. Overlap and adjacency only.
- Precomputed per-frame track storage. Only thresholded runs are persisted.
- Aggregates beyond `mean`, `median`, `var`. The registry has an extension
  point; adding `sd`/`min`/`max` later is a one-line change each.
- Any change to emuR compatibility of the on-disk ground truth. New state lives
  in the cache only and is rebuildable.

## 3. Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Track composition | Full temporal algebra | Track regions are first-class terms usable at any depth. |
| Track evaluation | Lazy per bundle, two-tier cache: windowed series then derived runs | The expensive step is independent of operator and threshold, so caching below the comparison makes threshold reuse exact rather than heuristic. |
| Property namespace | Flat `scope@name`, precedence metadata > media > file | One accessor to teach; shadowing warns. |
| Parser rollout | New parser first, legacy regex parser as fallback | Nothing that works today can break on upgrade. |
| Interval execution | Runs table plus SQL interval joins | Runs already live in the cache, so composition is an ordinary join and lazy plans stay SQL strings. |
| Time literals | SI unit mandatory on duration operands | `20` versus `20ms` versus `20s` is unrecoverable ambiguity; the grammar refuses it. |
| Region adjacency | Mandatory explicit tolerance, `A ->(10ms) B` | A frame grid is a DSP setting, so any implicit tolerance makes results depend on analysis configuration rather than on the query. |
| Track threshold units | Deduced from the track column name, assumed and reported when the query omits them, converted when they differ | superassp encodes the unit in the name (`fo_Hz`, `F1[Hz]`, `CPP_dB`), so the information is already there. |
| SSFF missing values | Handled upstream by `superassp::read_track()` | superassp 3.1.0 masks exact zeros in non-audio SSFF tracks by default. reindeer consumes `NA` and carries no sentinel logic of its own. |
| Numeric comparison | All six of `>`, `>=`, `<`, `<=`, `==`, `!=` wherever an operand is numeric | No arbitrary gaps in the operator table. |
| Track reading | `superassp::read_track()` | Dispatches SSFF and JSTF; uniform accessors across both. |
| Media probing | `av::av_media_info()` plus `file.info()` | superassp offers no header-only read; av returns precisely the specified field set. |

## 4. Grammar

Tokenizer plus precedence-climbing parser. Precedence, lowest binding first:
`|`, `&`, `^`, `->`, comparison. Outer brackets are optional at top level,
because a real parser no longer needs them to locate the split. Exactly one `#`
projection per query, enforced with a position-carrying error.

```ebnf
Query      = OrExpr ;
OrExpr     = AndExpr { "|" AndExpr } ;
AndExpr    = DomExpr { "&" DomExpr } ;
DomExpr    = SeqExpr { "^" SeqExpr } ;
SeqExpr    = Term { SeqOp Term } ;
SeqOp      = "->" | "->" "(" TimeLit ")" ;     (* tolerance form: NEW *)
Term       = "[" Query "]" | Predicate ;

Predicate  = [ "#" ] ( LabelPred | LevelRef | ScopePred
                     | CountPred | PosPred | TrackPred ) ;

LabelPred  = LevelName [ ":" Attribute ] StrOp Value ;      (* EQL2 *)
CountPred  = "Num" "(" LevelName "," LevelName ")" NumOp Integer ;   (* EQL2 *)
PosPred    = ( "Start" | "End" | "Medial" )
             "(" LevelName "," LevelName ")" BoolOp Boolean
           | "Medial" "(" LevelName "," LevelName "," Boolean ")" ;  (* EQL2 *)
BoolOp     = "=" | "==" | "!=" ;

(* NEW 1 *)
LevelRef   = LevelName [ ":" Attribute ] ;

(* NEW 2 *)
ScopePred  = Scope "@" Ident CmpOp Operand ;
Scope      = "bundle" | "session" | "db" ;          (* case-insensitive *)

(* NEW 3 *)
TrackPred  = Agg "(" TrackRef "," TimeLit ")" NumOp Threshold ;
Threshold  = Number [ TrackUnit ] ;
TrackUnit  = "Hz" | "kHz" | "dB" | "pct" | "Bark" | "mel"
           | "ERB" | "semitone" | "st" | TimeUnit ;
Agg        = "mean" | "median" | "var" ;
TrackRef   = TrackName [ "[" PosInt "]" ] ;         (* 1-based column *)

(* NEW 4 *)
Operand    = TimeLit | Number | String ;
TimeLit    = Number TimeUnit ;                      (* no bare form accepted *)
TimeUnit   = "ns" | "us" | "ms" | "s" | "min" ;

NumOp      = ">" | ">=" | "<" | "<=" | "==" | "!=" ;
StrOp      = "==" | "!=" | "=~" | "!~" ;
CmpOp      = NumOp | "=~" | "!~" ;
```

### 4.1 Bare level references

`LevelRef` is not sugar for `Level =~ ".*"`. It matches every item at the level
**without joining `labels`**, so it also matches items carrying no label for the
queried attribute, which `=~ ".*"` silently drops. It is both more correct and
cheaper. A bare `Word` is a valid complete query returning all words.

### 4.2 Mandatory SI units

The window argument of `TrackPred` is typed `TimeLit`, so `mean(fo, 20)` is a
parse error with a caret at the literal. The same applies to every
duration-typed operand, in track predicates, scope predicates and any future
function argument denoting a duration. `Word == "some" ^ bundle@duration > 100`
does not parse at all, rather than quietly meaning 100 milliseconds.

Unit legality is driven by the operand's **dimension**, taken from the registry
of §5:

| Dimension | Unit suffix | Example |
|---|---|---|
| duration | **required** | `bundle@duration > 100s`, `mean(fo,20ms)` |
| frequency | optional, checked | `bundle@sample_rate > 44.1kHz` or `> 44100` |
| track threshold | optional, deduced when absent (§7.2) | `mean(fo,20ms) > 300Hz` or `> 300` |
| count, bytes, timestamp, string | **forbidden** | `Num(Syllable, Phoneme) > 3s` rejected |

Duration is the only dimension where the unit is mandatory, because there is no
other record of what the number means. A track threshold needs no mandate: the
track itself carries its unit, so a bare number is resolved rather than
guessed.

Legacy note: EQL2 accepts a single `=` in position-function predicates
(`Start(Word, Syllable) = TRUE`) alongside `==`, and accepts the three-argument
`Medial(L1, L2, pos)` form. Both are preserved verbatim; `=` remains invalid
everywhere else, as today.

`min` is not an SI unit but is accepted alongside `ns`, `us`, `ms`, `s`; each
costs one lexer-table row. All literals normalise to milliseconds internally,
matching `start`/`end` in `segment_list`.

Timestamps are not durations. `bundle@mtime > "2024-01-01"` takes an ISO-8601
string.

Because EQL2 contains no time literals at all, mandatory units break nothing
that parses today.

### 4.3 Comparison operators

All six numeric operators are available on track predicates, on numeric,
duration and timestamp scope predicates, and on `Num()`. `=~` and `!~` remain
restricted to string-typed operands — labels, string metadata, `bundle@codec`;
applying them to a numeric property is a typed parse error rather than a silent
string coercion.

Float equality against a computed aggregate stays legal and is documented as a
footgun. No tolerance mechanism is introduced.

### 4.4 Terms that cannot stand alone or be projected

A scope predicate produces no items, so a query consisting only of scope
predicates — `bundle@duration > 100s` — raises `reindeer_eql_type_error`
directing the user to combine it with an item-producing term, for example
`Word ^ bundle@duration > 100s`. For the same reason `#` on a scope predicate is
an error: there is nothing to project.

`#` on a track predicate is valid and yields virtual segments (§9). `#` on a
bare level reference is valid and yields every item at that level.

### 4.5 Temporal degradation of `^` and `->`

`^` keeps its EQL2 `links`-walking semantics whenever both sides are
hierarchical annotation terms.

When either side is non-hierarchical:

- **Track region against annotation item:** true iff the intervals intersect,
  `r.start_ms <= i.end_ms AND r.end_ms >= i.start_ms`.
- **Scope property against anything:** the property's interval is the whole
  bundle or session, so overlap is vacuously true within scope and `^` collapses
  to a scope filter. This is exactly the reading "a bundle dominates all its
  annotations".

`->` keeps its exact EQL2 meaning between two annotation terms, where sequence
is structural — consecutive `seq_idx` at the same level — and no tolerance is
involved.

With a region on either side, the tolerance must be written into the query:

```
mean(fo,20ms) > 300 ->(10ms) Phonetic == t
```

The predicate is `0 <= b.start_ms - a.end_ms <= tol`. It is directional, so an
overlap — B beginning before A ends — is not adjacency and does not match. Bare
`->` with a region on either side is a parse error naming the `->(...)` form.

**Why the tolerance is mandatory rather than defaulted.** A track stores one
value per frame period, so a region boundary can only fall on that frame grid,
and the grid is a DSP configuration choice rather than a property of the
speech. Three consequences force an explicit number:

- Two runs of the same predicate can never be adjacent, because runs are
  maximal by construction. Region adjacency is only ever meaningful across
  different predicates.
- Different predicates usually mean different tracks and therefore different
  frame rates, so exact boundary equality between, say, a 5 ms f0 grid and a
  10 ms rms grid is almost never true. Without a tolerance the operator
  silently returns nothing.
- Annotation item boundaries come from `_annot.json` at the audio sample rate
  and sit at arbitrary times, so a region boundary coinciding with one exactly
  is a coincidence.

An adaptive default such as "one frame of the coarser track" would make the
same query return different results after the f0 step size changed from 5 ms to
10 ms, putting an analysis setting into query semantics. An option would put it
into a user's `.Rprofile`. Requiring it in the query keeps the query string a
complete description of its own result, which is the same rule already applied
to time literals in §4.2. There is consequently no
`options(reindeer.eql_adjacency_tol_ms)`.

Overlap is compared in milliseconds rather than samples. Annotation items and
SSFF tracks routinely carry different sample rates, and comparing in a common
unit removes a whole bug class.

## 5. Property registry

One table maps each `Scope@Ident` to a type, driving three things at once: unit
enforcement, operand coercion, and operator legality.

| Property | Scope | Type | Source |
|---|---|---|---|
| `duration` | bundle | duration | av |
| `sample_rate` | bundle | frequency | av |
| `channels`, `frames`, `bitrate` | bundle | count | av |
| `codec`, `layout`, `sample_fmt` | bundle | string | av |
| `size` | bundle | bytes | file.info |
| `mtime`, `ctime`, `atime` | bundle | timestamp | file.info |
| `mode`, `uid`, `gid` | bundle | count | file.info |
| `uname`, `grname` | bundle | string | file.info |
| `name` | bundle, session | string | cache |
| user fields | bundle, session, db | from `metadata_fields.field_type` | METADATA.json |

Each row's type determines its **dimension**, and the dimension determines unit
legality per the table in §4.2. `metadata_fields.field_type` has no `duration`
member, so metadata operands are never unit-bearing.

**Resolution order for `bundle@X`:** metadata, with inheritance resolved
bundle > session > db exactly as `get_metadata()` does, then media, then file.
`session@X` and `db@X` resolve metadata only — a session owns no media file, and
a property not found there is an error rather than a silent fall-through to the
bundle.

A metadata field shadowing a built-in raises `reindeer_eql_shadow_warning` once
per session. The flat namespace has no escape hatch; this is the accepted cost.

The EQL2 scope filters `Session == x` and `Bundle == x` are retained and are
exactly `session@name` and `bundle@name`.

## 6. Cache schema

New tables in `_emuDBcache.sqlite`, EAV-shaped to match the existing
`metadata_*` tables. All use `CREATE TABLE IF NOT EXISTS` and are created by a
migration run on cache open, gated on `PRAGMA user_version` — the cache
currently carries no schema version, so v3 introduces one.

```sql
CREATE TABLE IF NOT EXISTS bundle_properties (
  db_uuid TEXT, session TEXT, bundle TEXT,
  prop TEXT,
  value_num REAL,          -- canonical: duration ms, timestamps epoch seconds
  value_txt TEXT,
  src_mtime REAL,          -- media file mtime at probe time
  PRIMARY KEY (db_uuid, session, bundle, prop));

-- Tier 1: the expensive artefact. Independent of operator and threshold.
CREATE TABLE IF NOT EXISTS track_series (
  db_uuid TEXT, session TEXT, bundle TEXT,
  track TEXT, column_idx INTEGER, agg TEXT, window_ms REAL,
  frame_rate REAL, start_time_ms REAL, n_frames INTEGER,
  unit TEXT,                -- deduced native unit, NULL when undeducible
  series_schema INTEGER,    -- materialisation semantics version, see below
  v_min REAL, v_max REAL,   -- envelope in `unit`, for pruning without a read
  series BLOB,              -- qs-serialised double vector
  src_mtime REAL, last_used REAL,
  PRIMARY KEY (db_uuid, session, bundle, track, column_idx, agg, window_ms));

-- Tier 2: cheap, derived from tier 1 without touching signal files.
CREATE TABLE IF NOT EXISTS track_runs (
  db_uuid TEXT, session TEXT, bundle TEXT,
  track TEXT, column_idx INTEGER, agg TEXT, window_ms REAL,
  op TEXT, threshold REAL, threshold_unit TEXT,
  run_idx INTEGER,
  start_ms REAL, end_ms REAL,
  sample_start INTEGER, sample_end INTEGER, sample_rate REAL,
  value REAL, v_min REAL, v_max REAL,
  last_used REAL,
  PRIMARY KEY (db_uuid, session, bundle, track, column_idx, agg,
               window_ms, op, threshold, threshold_unit, run_idx));

CREATE INDEX IF NOT EXISTS track_series_pred_idx
  ON track_series(track, column_idx, agg, window_ms);
CREATE INDEX IF NOT EXISTS track_series_envelope_idx
  ON track_series(db_uuid, track, column_idx, agg, window_ms, v_min, v_max);
CREATE INDEX IF NOT EXISTS track_runs_pred_idx
  ON track_runs(track, column_idx, agg, window_ms, op, threshold, threshold_unit);
CREATE INDEX IF NOT EXISTS track_runs_scope_idx
  ON track_runs(db_uuid, session, bundle, track, agg, window_ms);
CREATE INDEX IF NOT EXISTS bundle_properties_prop_idx
  ON bundle_properties(db_uuid, prop);
```

**The predicate components are stored as columns, not folded into a hash.**
`track`, `column_idx`, `agg`, `window_ms`, `op` and `threshold` are each
queryable and indexed, so the planner can reason across cache entries —
find a series that serves a different threshold, or find runs already
materialised for a neighbouring one — with ordinary SQL rather than exact-match
hash lookup.

**Why two tiers.** Reading a track file and computing a windowed aggregate is
the expensive step, and it does not depend on `op` or `threshold`. Caching
below the comparison means one stored artefact answers every threshold exactly.
Caching above it, keyed on the threshold, does not: runs for `> 300` omit every
region whose mean lies in `(200, 300]`, so they cannot answer `> 200` at all,
and since only the run interval and its mean are retained they give `> 320`
only a containing envelope rather than its sub-stretches. Exactness is
available for the price of storing the series, so heuristic reuse of
thresholded runs is not attempted.

**Size.** A 5 ms frame step is 200 doubles per second, 1.6 KB/s raw. `qs` on a
smooth contour returns 3–5×, so roughly 14 MB per `(track, agg, window)`
combination per ten hours of audio. The existing cache warning threshold of
500 MB is well clear for corpus sizes reindeer targets.
`options(reindeer.eql_series_cache = FALSE)` disables tier 1 for users who
would rather re-read than store, at the cost of losing exact threshold reuse.

**Tier 1 presence is the evaluation marker,** so no separate negative-caching
table is needed: a bundle whose series is cached with `v_max <= threshold`
contributes no runs and is answered without deserialising the blob.

Invalidation is per bundle: a tier 1 row is stale iff `src_mtime` differs from
the track file's current mtime, or iff `series_schema` differs from the current
constant, at which point that bundle's series and every tier 2 row derived from
it are deleted and recomputed.

`series_schema` exists because the cache outlives package upgrades. Any change
to what a stored series means — a new windowing rule, a different aggregate
definition, or a raised `superassp` floor that changes what `read_track()`
returns — is shipped as a bump to the constant, which invalidates every cached
series rather than silently mixing values computed under two regimes.

All of this is cache, not ground truth. Deleting the tables costs only
recompute time.

## 7. Track evaluation

Track names in EQL are **track definition names** from `ssffTrackDefinitions` in
`_DBconfig.json`, resolved through `.list_ssffTrackDefinitions()` to a
`fileExtension` and a `columnName`. A query naming `fo` reads the bundle's
`.f0` file and selects its `F0` matrix. A track name absent from the definitions
is a parse-time error listing the defined names.

Reading goes through `superassp::read_track()`, which dispatches on extension to
`read_ssff()` (returning `AsspDataObj`) or `read_jstf()` (returning
`JsonTrackObj`). Both classes implement `tracks()`, `track_names()`, `rate()`,
`start_time()`, `n_records()` and `as_tibble()`, so run extraction is
format-blind and a track definition pointing at a JSTF extension works with no
additional code.

Frame index converts to milliseconds via `start_time()` and `rate()`.

The threshold on the right of a track predicate may carry a unit or omit one.
Omitted, it is taken to be in the track's own unit, which is deduced from the
column name; given, it is checked and converted. See §7.2.

### 7.1 Cache tiers and threshold reuse

Evaluating a track predicate against a bundle proceeds down the tiers, stopping
at the first that answers:

1. **Tier 2 hit.** Runs already exist for this exact
   `(track, column, agg, window, op, threshold)`. Join and stop.
2. **Tier 1 hit.** The windowed series is cached. Resolve units per §7.2, then
   check the stored envelope: for `> t` a series with `v_max <= t` yields no
   runs and the blob is never deserialised; for `< t` the test is `v_min >= t`.
   Otherwise deserialise, convert if needed, compare, run-length encode, insert
   tier 2 rows, join.
3. **Miss.** Read the track file through
   `superassp::read_track(file, tracks = <the one track needed>)`, deduce the
   unit (§7.2), compute the windowed aggregate, store tier 1 with its unit,
   schema version and envelope, then proceed as above. Passing `tracks =`
   skips converting and allocating every other track in the file, which matters
   for multi-track files such as formant analyses.

Only step 3 touches a signal file. A corpus already queried at one threshold
answers every other threshold on the same `(track, column, agg, window)` from
step 2, exactly and without disk access.

### 7.2 Unit deduction and conversion

superassp encodes a track's unit in its column name, in either the raw bracket
form (`fo[Hz]`, `F1[Hz]`) or the cleaned underscore form (`fo_Hz`, `CPP_dB`,
`H1_H2c_dB`) — see `superassp:::.parse_unit_from_colname()`. Recognised units
are `Hz`, `kHz`, `dB`, `pct`, `us`, `ms`, `s`, `Bark`, `mel`, `ERB`,
`semitone`, `st`.

**Deduction,** at tier 1 materialisation, first match wins:

1. The `units` attribute attached by `as_tibble()`, read with
   `units::deparse_unit()`. Authoritative, but only present for units
   `units::as_units()` recognises — so Hz and dB, not Bark, mel, ERB or
   semitone, which `.try_convert_to_units()` warns on and leaves plain.
2. The column-name suffix, by the convention above. `fm[1]` selects the first
   column of the `fm` matrix, whose cleaned name is `F1_Hz`, giving Hz.
3. Neither — `unit` is stored `NULL`.

The result is stored once in `track_series.unit` and never re-derived.

**Resolution against the query**, for a threshold `t` with optional unit `u`
against a series with deduced unit `w`:

| `u` | `w` | Behaviour |
|---|---|---|
| absent | known | Assume `w`. Report it once per query as `reindeer_eql_unit_message`, and record it in the canonical predicate string so the assumption is visible in `attribute` and in provenance, not only on the console. |
| absent | unknown | Direct numeric comparison, silently. This is the fallback path. |
| given | equal to `w` | Direct comparison. |
| given | convertible from `w` | Convert, then compare. |
| given | not convertible from `w` | `reindeer_eql_type_error` naming the pair. |
| given | unknown | `reindeer_eql_unit_warning`, then direct numeric comparison. |

**Conversion** takes whichever of two routes applies:

- **Linear**, via `units::set_units()`: Hz↔kHz, s↔ms↔us. The *threshold* is
  converted — one scalar — and the cached series is left in its native unit.
- **Monotone forward**, via superassp's `ucnv_hz_to_{bark,erb,mel,semitone}`:
  the *series* is converted. This direction is used because the inverse
  functions are not all exported — there is no `ucnv_mel_to_hz` or
  `ucnv_semitone_to_hz` — and it is sound because every one of these scales is
  strictly increasing in frequency, so `v > t` in Hz-space and in scale-space
  select the same frames. The `v_min`/`v_max` envelope converts forward under
  the same monotonicity, so pruning is unaffected.
- Anything else, `dB` against a frequency scale in particular, is a type error.
  `ucnv_db_and_hz_to_{phon,sone}` need a frequency alongside the level and are
  out of scope.

**The aggregate is computed in the track's native unit and the result is then
converted,** not the other way round. Since these scales are non-linear,
`hz_to_bark(mean(v))` and `mean(hz_to_bark(v))` genuinely differ, so the choice
is observable and is recorded here deliberately. Converting the aggregate is
what makes tier 1 reusable at all: one cached series of Hz means answers
thresholds in Hz, Bark, ERB, mel and semitone alike, whereas aggregating in
scale-space would need a separate cached series per unit.

A practical consequence, and a benign one: isolated unvoiced frames cannot
break a scale comparison. They have already become `NA` by the rule in §7.3 and
are dropped by `na.rm` while still in Hz. Only a window with no voiced frames at
all has no aggregate to convert, and evaluates `FALSE`.

`threshold_unit` is part of the tier 2 key, so `> 300` and `> 300Hz` and
`> 5Bark` are distinct cached predicates even where two of them agree.

### 7.3 Windowing semantics

These are stated explicitly because they are invisible until they bite.

- The window is centred on each frame and clamped at the signal edges.
  Truncated edge windows aggregate fewer frames rather than being dropped.
- **Every aggregate is computed with `na.rm = TRUE`** — `mean(x, na.rm = TRUE)`,
  `stats::median(x, na.rm = TRUE)`, `stats::var(x, na.rm = TRUE)`. A single
  missing frame never poisons a window. Trackers that emit `NA` for unvoiced or
  unanalysable frames, and conversions that leave `NA` where a value has no
  image on the target scale, therefore lose those frames rather than the window.
- A window with no non-`NA` frames evaluates `FALSE`. So does a `var` window
  with fewer than two non-`NA` frames, since variance is undefined there.
- **Missing values arrive as `NA` already.** SSFF has no representation for
  absence and stores `0` in its place, but that is superassp's problem to
  solve, not reindeer's: `read_track()` defaults to `zero_to_na = TRUE` and
  masks exact zeros in every non-audio SSFF track, leaving sampled audio alone
  because there `0` is silence, and leaving JSTF alone because JSON carries a
  real null. reindeer calls `read_track()` with its default and implements no
  sentinel rule of its own.
- Worth knowing when reading results, though it is not reindeer's behaviour: a
  genuinely measured zero in a non-audio SSFF track is masked too, because the
  format cannot distinguish it from absence. A window of nothing but such
  frames has no aggregate and evaluates `FALSE`. `superassp` 3.1.0 documents
  `zero_to_na = FALSE` as the escape hatch; reindeer does not expose it, since
  an option that changes query results is exactly what §4 and §7 exclude.
- A run is a maximal contiguous stretch of frames satisfying the comparison. Its
  interval spans the first frame's start to the last frame's end. Runs are
  returned whatever their length; a minimum duration is a
  `dplyr::filter(end - start >= 20)` on the collected result, where the
  threshold stays visible in the script.
- The stored `value` is the mean of the window values across the run; `v_min`
  and `v_max` on the run record its extremes.
- Bare `fm` on a multi-column track is a parse error reporting the column count,
  rather than silently meaning `fm[1]`.

## 8. Planner and execution

Track terms are the only expensive construct in the language, so the planner
exists to avoid evaluating them.

1. Parse to AST.
2. Partition terms into cheap — label, level reference, scope, count, position —
   and expensive — track.
3. If any track term is present, evaluate the cheap conjunctive restriction
   first as `SELECT DISTINCT session, bundle`, then materialise runs only for
   that bundle set, walking the cache tiers of §7.1. Envelope pruning runs as a
   SQL predicate against `track_series` before any blob is fetched, so bundles
   that cannot satisfy the threshold cost one index lookup.
4. Emit a single SQL statement joining `items`/`labels` against `track_runs` on
   `(db_uuid, session, bundle)` with the interval predicates from §4.5.
   `lazy_segment_list` holds that string, so lazy pipelines survive track terms.

**Stated limit:** only conjunctive context restricts. A track term under `|`
with no bundle-restricting sibling falls back to scanning every bundle. The
documentation says so plainly rather than implying the planner is cleverer than
it is.

## 9. Result semantics

Virtual segments projected by `#` on a track term are ordinary `segment_list`
rows:

| Column | Value |
|---|---|
| `labels` | run aggregate formatted `%.4g` |
| `level` | track definition name |
| `attribute` | canonical printed predicate, e.g. `mean(fo[1],20ms)` |
| `type` | `"SEGMENT"` |
| `start_item_id`, `end_item_id` | `NA_integer_` |
| `start_item_seq_idx`, `end_item_seq_idx` | `NA_integer_` |
| `start`, `end` | run bounds in ms |
| `sample_start`, `sample_end`, `sample_rate` | from the track |
| `db_uuid`, `session`, `bundle` | as usual |

The `segment_list` validator at `R/segment_list_classes.R:60` checks only
presence plus the types of `labels`, `start`, `end`, `db_uuid`, `session` and
`bundle`, so `NA_integer_` item ids need no validator change.

`biographize()` and `quantify()` need only session, bundle, start and end, and
so work on virtual segments unchanged. `ascend_to()`, `descend_to()` and
`scout()` cannot — they walk `links` rows that do not exist — and raise
`reindeer_virtual_segment_error` explaining why. Provenance records the track
operation like any other step.

## 10. Conditions

Extending the hierarchy in `R/conditions.R`, all inheriting `reindeer_error` or
`reindeer_warning`:

- `reindeer_eql_parse_error` (subclass of `reindeer_query_error`) — carries
  `query`, `offset`, `expected`; message renders a caret under the offending
  token.
- `reindeer_eql_type_error` (subclass of `reindeer_query_error`) — unit on an
  operand whose dimension forbids one, missing unit on a duration operand, a
  threshold unit not convertible from the track's own unit, `=~` on a numeric
  property, unknown track or property name.
- `reindeer_virtual_segment_error` (subclass of `reindeer_query_error`) —
  hierarchy navigation attempted on item-less rows.
- `reindeer_eql_unit_warning` (subclass of `reindeer_query_warning`) — a unit
  given for a track whose own unit could not be deduced; comparison falls back
  to bare numbers.
- `reindeer_eql_unit_message` — the unit assumed for a bare threshold, emitted
  once per query and muffleable.
- `reindeer_eql_shadow_warning` (subclass of `reindeer_query_warning`).
- `reindeer_eql_fallback_warning` (subclass of `reindeer_query_warning`).

## 11. Rollout and compatibility

The v3 parser runs first. On `reindeer_eql_parse_error` it retries through the
legacy regex parser; if that succeeds, it warns with
`reindeer_eql_fallback_warning` quoting the query.
`options(reindeer.eql_fallback = "warn" | "silent" | "error")`, default
`"warn"`, scheduled for removal at 2.0.

The gate that makes the fallback safe rather than a mask: **the existing 1074
EQL-parity tests must pass with `reindeer.eql_fallback = "error"`.** Otherwise a
parser regression silently becomes a fallback and nobody notices.

The `superassp` floor rises to 3.1.0, the first release whose `read_track()`
masks the SSFF zero sentinel by default and accepts `tracks =` to skip
unselected tracks. Below that floor the sentinel would reach reindeer as a
measurement, so the floor is a correctness requirement rather than a
convenience.

`av` is added to `Suggests`; it is already in superassp's dependency tree. A
query resolving to a media property without `av` installed raises
`reindeer_missing_companion_error`, which already exists.

Cache migration is additive and idempotent, gated on `PRAGMA user_version`.
Existing caches gain the new tables on next open; no rebuild is required.

## 12. Testing

- `test_eql3_lexer.R` — unit literals, suffix rejection on non-duration
  operands, missing-unit rejection, offset reporting.
- `test_eql3_grammar.R` — precedence, optional outer brackets, single-`#`
  enforcement, bare level references including the no-label case that
  `=~ ".*"` drops.
- `test_eql3_scope.R` — resolution order, shadow warning, probe invalidation on
  mtime change, `session@` refusing media properties.
- `test_eql3_tracks.R` — window edges, run boundaries, JSTF track definitions
  read through the same path, and `NA` handling: a window with one missing
  frame aggregates the rest, a wholly missing window is `FALSE`, a `var` window
  with one non-`NA` frame is `FALSE`, and `NA` arriving from `read_track()`
  propagates correctly through windowing, aggregation and run extraction. The
  zero-masking itself is superassp's contract and is tested there; reindeer
  asserts only that it calls `read_track()` without overriding `zero_to_na`.
- `test_eql3_units.R` — deduction from both name forms and from the `units`
  attribute; assumption reported and recorded in `attribute`; linear conversion
  of the threshold; monotone forward conversion of the series giving results
  identical to converting the threshold where an inverse does happen to exist;
  envelope pruning correct after forward conversion; the aggregate converted
  rather than the frames, asserted against a hand-computed case where the two
  orderings differ; incompatible pair rejected;
  undeducible unit falling back to bare comparison. Plus a drift guard that
  skips when superassp is absent and otherwise asserts reindeer's known-unit
  list matches `superassp:::.parse_unit_from_colname()`.
- `test_eql3_cache.R` — tier 2 exact hit; tier 1 serving a threshold it was not
  built for, with results identical to a cold computation; envelope pruning
  skipping deserialisation; `src_mtime` invalidation cascading tier 1 to tier 2;
  `reindeer.eql_series_cache = FALSE` still correct.
- `test_eql3_temporal.R` — overlap and adjacency against hand-built fixtures
  with deliberately mismatched frame rates; bare `->` on regions rejected;
  `->(t)` directional, so an overlapping pair does not match; same-predicate
  adjacency empty by construction; annotation-to-annotation `->` unchanged from
  EQL2.
- `test_eql3_fallback.R` — fallback warns, `"error"` mode refuses, parity suite
  green under `"error"`.

Fixtures use the `ae` demo database via `reindeer:::create_ae_db()`, with
synthetic track files written for the deterministic windowing cases.

## 15. Future work

- Additional aggregates (`sd`, `min`, `max`) via the registry extension point.
- Named Allen relations beyond overlap and adjacency, if demand appears.
- Restriction pushdown through disjunction.
- Quantising the stored series to `int16` if the compressed blobs prove large
  on long-form corpora.
- Aligning `quantify()` with `read_track()`'s masking. `quantify()` calls DSP
  functions with `toFile = FALSE` (`R/tidy_trackdata_helpers.R:182`) and reads
  their in-memory output directly, so it never passes through `read_track()`
  and `zero_to_na` never applies. `quantify(segs, trk_pitch_ksv, .at = 0.5)`
  therefore reports `0` for an unvoiced frame while `mean(fo,20ms)` treats the
  same frame as missing — and with `enrich()` writing those zeros to SSFF, the
  two verbs disagree about one file. The divergence is pre-existing and out of
  scope here, but v3 is what makes it visible, and it should not outlive this
  work by long.
- Asking superassp to export its unit parser so reindeer's mirrored known-unit
  list can be deleted, and to export `ucnv_mel_to_hz` / `ucnv_semitone_to_hz`
  so threshold-side conversion becomes available for every scale.
- A sub-namespaced accessor (`bundle@media.duration`) if flat-namespace
  shadowing proves painful in practice.
